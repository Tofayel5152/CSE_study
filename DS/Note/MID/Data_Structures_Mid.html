Elementary data organization

Elementary Data Organization: in which and how many formats data can be stored.
Data = a value or a set of values. The term indicates both the singular form (data item) and the plural form (group items).
Elementary items: data items that cannot be divided into sub-items. Group items are NOT elementary items — they can be divided into sub-items.
Example: Name → group item (not an elementary item) → first name – middle name – last name. Roll → data item → single item.
Data vs Information: data is just a value; information is a value with significance or importance.
Flow: Data → Data type → Entity → Attributes → Information   (Field → Record)

Name group item No — can be divided first name – middle name – last name

Fields, records & files

A collection of data is organized into a hierarchy of fields (attributes) → records (entity) → files (entity set).
Attributes → the information in each section of a column, like ID, Name, Age.
Entity → the information of each row, like 001 Abid 27. (Something that has certain attributes or properties which may be assigned values.)
Entity set → a group of entities makes an entity set, like the full table. (Entities with similar attributes constitute an entity set.)
Domain of an attribute → the range of attribute values of an entity set.
Domain is a set of all possible attribute values.
Primary key → a certain attribute value that can specify or determine the entity of a file (entity set), like ID (unique for each entity).
The values k₁, k₂, … in such a field (attribute) are called keys or key values.
ID Name Age
001 Abid 27
002 Adib 25

Information

Information → data with its attributes; meaningful data or processed data.
Data → procedure to process data → Information.
Example: 34 → data.
“34 is the age of a person” → information (the data with its meaning/attribute).

Data types & Abstract Data Type (ADT)

Data type: a term which refers to the kind of data that may appear in computation. Two kinds: built-in and abstract.
Built-in: with every programming language there is a set of data types called built-in data types — int, float, char, double, bool, etc.
Abstract: the programmer’s own (created) data type is termed an abstract data type or user-defined data type. It can be created using a structure / class (in C/C++).
ADT = Abstract Data Type: a type (or class) for objects whose behavior is defined by a set of values and a set of operations.
In simple words: an ADT tells what data it holds and what operations you can do (e.g. a Stack: push, pop) — but not how it is coded or stored in memory. The ADT definition mentions what operations are to be performed but not how they are implemented; it does not specify how data will be organized in memory or what algorithms will be used. That is why it is called “abstract”: it gives an implementation-independent view.
Abstraction = the process of providing only the essentials and hiding the details. 
struct Student { int roll; char name[20]; };   // user-defined type (ADT-style)
// Stack ADT: values = list of items, operations = push(x), pop(), top(), isEmpty()

Data structure & algorithm

Data structure: the logical or mathematical model of a particular organization of data. The choice of a data model depends on two considerations: (1) it must reflect the actual relationships of the data in the real world; (2) it should be simple enough that one can effectively process the data when necessary.
Algorithm: a finite set of steps, written in order, to solve a problem. Not a complete code or program — just the core logic of a program. Written as pseudo code or flow chart.
Algorithm analysis: the process of comparing two algorithms, measured on the basis of time and space complexity. There are 2 types: A priori and A posteriori.
A priori analysis
Analysis before execution of the algorithm.
Gives an approximate value.
A posteriori analysis
Analysis after execution of the algorithm.
Gives the exact value.

Classification of data structures

Linear data structure: all the elements form a sequence or maintain a linear ordering.
Non-linear data structure: no such sequence of elements is found; all the elements are distributed over a plane.

Array (1-D and multi-dimensional)

Array: a finite, ordered collection of homogeneous data elements. Ex: an array of all int.
Two types: one-dimensional (linear) and multi-dimensional (2D, 3D, etc.).
One-dimensional array: a list of a finite number n of (similar) data elements, referenced respectively by a set of n consecutive numbers (0, 1, 2, …, n−1).
Elements: if A is the name of a 1D array → A[0], A[1], A[2], … , A[n−1].
Note: in the data structure course we will be reading the elements from 1 to n → A[1], A[2], … , A[n].
The number K in A[K] is called the subscript and A[K] is called the subscripted variable.

Linked list — array vs linked list

Array (10, 20, 100, 50, 3): only the values are kept; they are stored side by side in consecutive memory locations.
Linked list: the value and an address are kept; elements need not be adjacent in memory.
Linked list = an ordered collection of finite (n), homogeneous (similar) data elements called nodes, where linear order is maintained by means of links or pointers.
Every node contains: 1st part — the information or value of the element. 2nd part (known as link field or pointer field) — contains the address of the next node.
Special pointers: Start (or head) — contains the address of the first node. Null pointer (✕) — a special value that indicates the end of the list.

Stack, queue, tree, graph

Stack — a “last-in first-out” (LIFO) system: an ordered collection of homogeneous data elements where data insertion and deletion take place only at one end, called Top. Ex: a stack of dishes. Inserting 4→3→2→1 and deleting 1→2→3→4: we can’t take a dish from the middle or last.
Queue — a “first-in first-out” (FIFO) system: an ordered collection of homogeneous data elements where deletion can only be at the front end of the list and insertion only at the rear end. Ex: people in a line at a bank counter.
Tree: a data structure that reflects hierarchical relationship between various elements. Ex: hierarchical relation in a company.
Graph: a data structure that reflects a relationship between pairs of elements which is not necessarily hierarchical in nature. Ex: airline flights between cities.

Data structure operations

Traversing: processing (traveling) each element in the list.
Search: finding the location of the element with a given value, or the record with a given key.
Insertion: adding a new element to the data structure.
Deletion: removing an element.
Sorting: arranging the elements in some type of order. (Applies to array/list-type structures; not to graph, stack, queue, tree.)
Merging: combining two sorted lists into a single list.

Complexity of an algorithm

An algorithm is a finite step-by-step list of well-defined instructions for solving a particular problem. The time and space it uses are two major measures of its efficiency.
The complexity of an algorithm M is a function f(n) which gives the running time (time complexity) and storage space (space complexity) requirement of the algorithm in terms of the size n of the input data.
Time complexity: how long a program takes to run. It is measured not in seconds but in number of steps, e.g. O(n), O(1). Summing 1…N with a loop takes O(n); with a very large number it takes too much time. O(n): input n → n tasks. O(1): input is n but the work is done in one line / one fixed way (no loop). O(n²): a loop containing a second loop.
Space complexity: the storage required by an algorithm is a simple multiple of the data size n, or the size of the input variables. 
// prime check: loop only up to sqrt(n)
bool prime = true;
for (int i = 2; i <= sqrt(n); i++) {
    if (n % i == 0) { prime = false; break; }
}
cout << (prime ? "prime" : "not prime");   // O(sqrt n) -- far faster than looping i < n, which is O(n)

Time–space trade-off

The time–space trade-off refers to a choice between algorithmic solutions of a data-processing problem that lets one decrease the running time of a solution by increasing the space to store the data, and vice-versa.
Swap with temp: 3 tasks, 3 variables → less time, more space.
Swap without temp: 6 tasks, 2 variables → more time, less space. Not every program is allowed to / uses this trade-off. 
int a=5, b=2, temp;        int a=5, b=2;
temp = a;                    a = a + b;
a = b;                       b = a - b;
b = temp;                    a = a - b;

Floor, ceiling, integer & absolute value

Floor ⌊x⌋: the greatest integer that does not exceed x. ⌊1.2⌋ = 1 (nearest integer below); ⌊−3.5⌋ = −4.
Ceiling ⌈x⌉: the least integer that is not less than x. ⌈1.2⌉ = 2 (nearest integer above); ⌈−3.5⌉ = −3.
If x is an integer, ⌊x⌋ = ⌈x⌉; otherwise ⌊x⌋ + 1 = ⌈x⌉.
Integer value INT(x) (typecast): converts x to an integer by deleting (truncating) the fractional part. INT(3.14) = 3, INT(−8.5) = −8.
Absolute value ABS(x) or |x|: the greater of x and −x. |−15| = 15, |3| = 3, ABS(−8.5) = 8.5.

Remainder function & congruence

Let k be an integer and M a positive integer. k (mod M) (also k % M) = the integer remainder when k is divided by M. 5 % 3 = 2 because 5 = 1·3 + 2.
So k (mod M) = r, a unique integer with 0 ≤ r < M, and k = Mq + r (q an integer).
Congruence: a ≡ b (mod M) iff M divides (a − b) — both leave the same remainder on division by M.
Examples: 15 ≡ 20 (mod 5); 17 ≡ 22 (mod 5); 22 ≡ 2 (mod 5).

Factorial, Fibonacci, permutation & combination

n! = 1×2×3×…×(n−2)×(n−1)×n. int covers 0! to 12!; long long covers up to 20!; more needs a string.
Fibonacci: 0, 1, 1, 2, 3, 5, 8, … with Fn = Fn−1 + Fn−2.
Permutation (order matters; choosing and ordering): nPr = n!/(n−r)!.
Combination (order does not matter; choosing r boxes from n): nCr = n!/(r!(n−r)!).
Example with letters R B P N, choosing 3: nPr = 4×6 = 24 ways (each choice like RBN has 6 orderings: RBN, RNB, NRB, NBR, BNR, BRN). nCr = 4 ways: RBN, RPN, RBP, BPN.

Summation, exponents & logarithms

Σ: 1+2+3+…+n = n(n+1)/2 · 1²+2²+…+n² = n(n+1)(2n+1)/6 · Σk³ = (n(n+1)/2)².
Exponent: aⁿ = a×a×…×a (n times).
Logarithm: bʸ = x ⇔ y = logb x — how many times x can be divided by b until it reaches 1. log₁₀ 1000: 1000/10 = 100/10 = 10/10 = 1 → 3 divisions → 3. log₂ 8 = 3 (2×2×2 = 2³).
Common log (base 10), natural ln (base e), binary lg or log₂ (base 2). In CSE we normally use binary logarithms: log x means log₂ x.

Algorithmic notation

An algorithm is a finite step-by-step list of well-defined instructions for solving a particular problem. Its formal presentation has two parts: first a paragraph telling the purpose, identifying the variables and listing the input data; second the list of steps to be executed.
Steps, control, exit: steps execute one after the other beginning with Step 1 unless indicated otherwise. Control may be transferred by “Go to Step n”. Several statements in one step run left to right. The algorithm is complete when Exit is met.
Comments: each step may carry a bracketed comment giving its main purpose. Variable names use capital letters; single letters (upper/lower) serve as counters or subscripts.
Assignment: dots-equal := (some texts use ← or =). Input: Read: variable names. Output: Write: messages and/or variable names. An algorithm is also known as a procedure or pseudocode.

Algorithm: largest element in an array

A nonempty array DATA with N numerical values is given. The algorithm finds the location LOC and the value MAX of the largest element; K is a counter. 

Algorithm 1: Largest element in an array (with "Go to")
Step 1. [Initialize] Set K := 1, LOC := 1 and MAX := DATA[1].
Step 2. [Increment counter] Set K := K + 1.
Step 3. [Test counter] If K > N, then:
            Write: LOC, MAX and Exit.
Step 4. [Compare and update] If MAX < DATA[K], then:
            Set LOC := K and MAX := DATA[K].
Step 5. [Repeat loop] Go to Step 2.
Algorithm 2: Largest element in an array (Repeat-while)
Step 1. [Initialize] Set K := 1, LOC := 1 and MAX := DATA[1].
Step 2. Repeat Steps 3 and 4 while K <= N:
Step 3.     If MAX < DATA[K], then:
                Set LOC := K and MAX := DATA[K].
Step 4.     Set K := K + 1.
        [End of Step 2 loop]
Step 5. Write: LOC, MAX.
Step 6. Exit.

Flowchart: largest element

The loop returns to K := K + 1 from both the “No” of MAX < DATA[K] and from the update box.

Control structures: sequence & selection

Three types of logic / flow of control: sequence (sequential flow), selection (conditional), iteration (repetitive).
Sequence logic: unless instructions say otherwise, modules run in clear order — shown explicitly by numbered steps or implicitly by the order modules are written. Most processing, even of complex problems, follows this initial flow pattern.
Selection logic uses conditions to select one of several alternative modules; the structures are called conditional or if structures. Three types: single, double, multiple alternative.
Single: If condition, then: [Module A] [End of if structure] — if true A runs, otherwise A is skipped and control moves on. Double: If condition, then: [A] Else: [B] — A if true, B if false. 
Multiple alternatives:
If condition(1), then: [Module A1]
Else if condition(2), then: [Module A2]
...
Else if condition(n), then: [Module An]
Else: [Module B]
[End of if structure]

Only one module runs: if condition (1) is true A₁ runs; if false, condition (2) is checked, and so on; if all conditions are false, Module B runs.

Flowcharts of selection & iteration

Iteration logic (repetitive flow)

Two types: the Repeat-for loop and the Repeat-while loop. Each begins with a Repeat statement followed by a module called the body of the loop.
Repeat-for: Repeat for k = R to S by T: [Module] [End of loop] — R initial value, S end value, T increment, k control variable.
Repeat-while: Repeat while condition: [Module] [End of loop] — the loop executes until the condition is false.

Algorithm: quadratic equation

Inputs the coefficients A, B, C of a quadratic equation and outputs the real solutions, if any. 

Step 1. Read: A, B, C.
Step 2. Set D := B² − 4AC.
Step 3. If D > 0, then:
          (a) Set X1 := (−B + √D)/(2A) and X2 := (−B − √D)/(2A).
          (b) Write: X1, X2.
        Else if D = 0, then:
          (a) Set X := −B/(2A).
          (b) Write: 'UNIQUE SOLUTION', X.
        Else:
          Write: 'NO REAL SOLUTION'.
        [End of if structure]
Step 4. Exit.

Subalgorithms

A subalgorithm (routine / subroutine / function) is a complete and independently defined algorithmic module used (invoked or called) by a main algorithm or by another subalgorithm. It receives values, called arguments, from the originating (calling) algorithm, performs computations, and sends back the result.
It is defined independently so it can be called by many different algorithms, or at different times in the same algorithm. Its relation to an algorithm is like a subprogram to a main program.
Differences: a subalgorithm normally has a heading NAME(PAR₁, PAR₂, …, PARₖ), and it has a Return statement instead of an Exit statement.

Examples: MEAN and SWITCH

MEAN is the name; A, B, C are parameters; Return puts AVE in parentheses — its value goes back to the calling program. Call: Set TEST := MEAN(T1,T2,T3) — arguments T₁,T₂,T₃ (test scores) transfer to A,B,C; MEAN runs and AVE is assigned to TEST.

SWITCH returns two values, which a single return value cannot hold, so it is invoked with a Call statement: B and A replace AAA and BBB, SWITCH does its work, and the values in B and A come back switched. 

Function: MEAN(A,B,C)
  1. Set AVE := (A+B+C)/3.
  2. Return(AVE).
SWITCH(AAA, BBB)
  1. Set TEMP := AAA, AAA := BBB and BBB := TEMP.
  2. Return.
Call SWITCH(B, A)

Linear arrays

The elements of a linear array are referenced by an index set of n consecutive numbers and are stored in successive memory locations.
Length (size, number of elements) = UB − LB + 1. Word size w = bytes per element (int = 4, char = 1). LB = lower bound (first index).
LOC(LA[K]) = BASE(LA) + w·(K − LB) — address of the Kth element; BASE(LA) is the address of the first element.
BASE w LB K →

Example: AUTO (int, w = 4), LOC(AUTO[1932]) = 200 → LOC(AUTO[1965]) = 200 + 4·33 = 332

Traversing a linear array

Let LA be a linear array with lower bound LB and upper bound UB. Traversing visits every element, applying an operation PROCESS to each.

Example: array AUTO records automobiles sold each year 2000–2019. 

Algorithm: Traversing LA (Repeat-while version)
Step 1. Set K := LB.
Step 2. Repeat Steps 3 and 4 while K <= UB:
Step 3.     Apply PROCESS to LA[K].
Step 4.     Set K := K + 1.
        [End of loop]
Step 5. Exit.
Algorithm: Traversing LA (Repeat-for version)
Step 1. Repeat for K = LB to UB:
            Apply PROCESS to LA[K].
        [End of loop]
Step 2. Exit.
Module a: find the number NUM of years in which more than 300 automobiles were sold
Step 1. Set NUM := 0.
Step 2. Repeat for K = 2000 to 2019:
            If AUTO[K] > 300, then:
                Set NUM := NUM + 1.
        [End of loop]
Step 3. Return.
Module b: print each year and the number of automobiles sold in that year
Step 1. Repeat for K = 2000 to 2019:
            Write: K, AUTO[K].
        [End of loop]
Step 2. Return.

Inserting into a linear array

Adding an extra value to an array. If there is enough space: at the end → Arr[n+1] = new element; in the middle → the elements from the target location to the end must be moved downward and the length becomes n+1. If there is not enough space, inserting makes the end value vanish.

Time complexity O(n).

Algorithm: INSERT(LA, N, K, ITEM)
Here LA is a linear array with N elements and K is a positive integer such that K <= N.
This algorithm inserts an element ITEM into the Kth position in LA.
Step 1. Set J := N.
Step 2. Repeat Steps 3 and 4 while J >= K:
Step 3.     Set LA[J+1] := LA[J].
Step 4.     Set J := J - 1.
        [End of loop]
Step 5. Set LA[K] := ITEM.
Step 6. Set N := N + 1.
Step 7. Exit.

Deleting from a linear array

Removing one element. At the end → n = n − 1; in the middle → every following element moves one location upward and n = n − 1.

Time complexity O(n).

Algorithm: DELETE(LA, N, K, ITEM)
Here LA is a linear array with N elements and K is a positive integer such that K <= N.
This algorithm deletes the Kth element from LA.
Step 1. Set ITEM := LA[K].
Step 2. Repeat for J = K to N - 1:
            Set LA[J] := LA[J+1].
        [End of loop]
Step 3. Set N := N - 1.
Step 4. Exit.

Bubble sort

Compare neighbours: if already ordered (small to large) do nothing and move on; if not, swap them. Two loops are needed → O(n²); in the worst case every index is checked. 
5 10 3 7 9   pass 1: 5 3 7 9 10   pass 2: 3 5 7 9 10   sorted
BUBBLE(DATA, N)   sorts the elements in DATA.
Step 1. Repeat Steps 2 and 3 for K = 1 to N−1.
Step 2.   Set PTR := 1.
Step 3.   Repeat while PTR <= N−K:
            (a) If DATA[PTR] > DATA[PTR+1], then: Interchange DATA[PTR] and DATA[PTR+1].
            (b) Set PTR := PTR + 1.
Step 4. Exit.

Searching & linear search

Let DATA be a collection of data with specific information given about ITEM. Searching = finding the location LOC of ITEM in DATA, or printing a message that ITEM was found or not. Found → search successful; otherwise unsuccessful.
Linear (sequential) search: compare ITEM with each element of DATA one by one, traversing DATA sequentially. Example DATA = 5, 15, 7, 10, find 7: DATA[1]=7? no; DATA[2]=7? no; DATA[3]=7? yes → found, LOC = 3. 
Algorithm: Linear search (DATA, N, ITEM)
Step 1. Set K := 1 and LOC := 0.
Step 2. Repeat Steps 3 and 4 while LOC = 0 and K <= N:
Step 3.     If ITEM = DATA[K], then:
                Set LOC := K.
Step 4.     Set K := K + 1.
        [End of loop]
Step 5. If LOC = 0, then:
            Write: ITEM is not in the array DATA.
        Else:
            Write: LOC is the location of ITEM.
        [End of If structure]
Step 6. Exit.

Linear search: add the item if not found

LINEAR(DATA, N, ITEM, LOC) — finds LOC or sets LOC = 0 if unsuccessful, and then sets the last element as ITEM (inserting it at the end). 

Algorithm: LINEAR(DATA, N, ITEM, LOC)  (adds ITEM at the end if it is not found)
Step 1. Set K := 1 and LOC := 0.
Step 2. Repeat Steps 3 and 4 while LOC = 0 and K <= N:
Step 3.     If ITEM = DATA[K], then:
                Set LOC := K.
Step 4.     Set K := K + 1.
        [End of loop]
Step 5. If LOC = 0, then:
            Set LOC := N + 1 and DATA[LOC] := ITEM.
            Write: Now ITEM is in the location LOC.
        Else:
            Write: LOC is the location of ITEM.
        [End of If structure]
Step 6. Exit.

Binary search

Used when DATA is sorted (numerically or alphabetically). log₂N = how many times N can be divided by 2 until it gives 1: log₂16 = 4 (16/2 = 8/2 = 4/2 = 2/2 = 1).
BEG, END, MID denote the beginning, end and middle locations of the current segment. Each step divides the (improved) array length by 2. Example X = [0, 1, 5, 9, 12] (positions 1–5), find 9: MID = INT((1+5)/2) = 3, X[3] = 5 < 9 → BEG = 4; MID = INT((4+5)/2) = 4, X[4] = 9 → LOC = 4.
Time complexity O(log₂N). Limitations: the list/array must be sorted; one must have direct access to the middle element. 
Algorithm: BINARY(DATA, LB, UB, ITEM, LOC)
Step 1. Set BEG := LB, END := UB and MID := INT((BEG + END)/2).
Step 2. Repeat Steps 3 and 4 while BEG <= END and DATA[MID] != ITEM:
Step 3.     If ITEM < DATA[MID], then:
                Set END := MID - 1.
            Else:
                Set BEG := MID + 1.
            [End of If structure]
Step 4.     Set MID := INT((BEG + END)/2).
        [End of Step 2 loop]
Step 5. If DATA[MID] = ITEM, then:
            Set LOC := MID.
        Else:
            Set LOC := NULL.
        [End of If structure]
Step 6. Exit.

Two-dimensional arrays

A multi-dimensional array is an array of arrays: 2D, 3D, … The 2D (matrix) array is the most commonly used; it presents information in a structured, tabular manner using rows and columns and uses two subscripts.
An array can be declared with multiple dimensions: 1D arr[3]; 2D arr[3][4] = 3×4 = 12 elements; 3D arr[2][3][3] (two 2D arrays).

Two-dimensional arrays: A[m,n]

A two-dimensional m×n array A is a collection of m·n data elements, each specified by a pair of integers (j, k) called subscripts with 1 ≤ j ≤ m and 1 ≤ k ≤ n. The element is written Ajk, A[j,k] or A[j][k].
Two-dimensional arrays are also known as matrices (mathematics) or tables (business applications).

Memory representation of a 2D array

A 2D array is rectangular, but memory is sequential, so it is stored as a block of (m×n) sequential locations in one of two ways: row-major (elements stored row by row) or column-major (column by column).
Take A[2][3] = [4 5 6; 7 8 9] → row-major: 4 5 6 7 8 9; column-major: 4 7 5 8 6 9.
Let M = base address of the matrix, w = memory cells per element (int 4, float 4), r = number of rows, c = number of columns, lr = lower index of row, lc = lower index of column; (i, j) = index of the element.
Row-major: Address(A[i][j]) = M + w·(c(i − lr) + (j − lc)). Column-major: Address(A[i][j]) = M + w·((i − lr) + r(j − lc)).

Matrices: transpose & sum

An m×n matrix is an array of m·n numbers arranged in m rows and n columns: A = [Aij] with A₁₁ … A₁ₙ down to Am1 … Amn.
Transpose: a flipped version of the original. Transposing an (m×n) matrix gives an (n×m) matrix with Mᵀ(j,i) = M(i,j), 1 ≤ i ≤ m, 1 ≤ j ≤ n.
Sum is only defined for matrices of the same dimensions: A + B is the (m×n) matrix obtained by adding corresponding elements. A = [1 −2; 0 4], B = [3 0; 2 −3] → A + B = [1+3 −2+0; 0+2 4+(−3)] = [4 −2; 2 1].

Matrix product & MATMUL

Product AB is defined only when the number of columns in A equals the number of rows in B. A is (m×p), B is (p×n) → AB is (m×n).
AB₁₁ = A₁₁B₁₁ + A₁₂B₂₁
AB₁₂ = A₁₁B₁₂ + A₁₂B₂₂
AB₂₁ = A₂₁B₁₁ + A₂₂B₂₁
AB₂₂ = A₂₁B₁₂ + A₂₂B₂₂.
In general ABij = Ai1B1j + Ai2B2j + … + AipBpj = Σk=1..p AikBkj 
Algorithm: MATMUL(A, B, C, M, P, N)
A is an M x P matrix array and B is a P x N matrix array.
This algorithm stores the product of A and B in the M x N matrix array C.
Step 1. Repeat Steps 2 to 4 for I = 1 to M:
Step 2.     Repeat Steps 3 and 4 for J = 1 to N:
Step 3.         Set C[I, J] := 0.
Step 4.         Repeat for K = 1 to P:
                    Set C[I, J] := C[I, J] + A[I, K] * B[K, J].
                [End of K loop]
            [End of J loop]
        [End of I loop]
Step 5. Exit.

Algebra of matrices: kinds of matrices

Sparse matrices

Matrices which have the majority of their elements as zero, e.g. [0 0 1 2; 1 0 0 3; 1 0 0 0]. If the number of zeros exceeds (n·m)/2 (m, n the dimensions), the matrix is sparse.
Why use it instead of a simple matrix? Storage: fewer non-zeros, less memory (avoids zeros). Computing time: can be saved by logically designing algorithms that traverse only non-zero elements.
Sparse matrices are of two main types:
1. Diagonal matrices — non-zero elements are stored in the leading diagonal. Its variant is the tridiagonal matrix: the diagonal and the one above and below it have non-zero elements.
2. Triangular matrices — non-zero elements are placed below the leading diagonal (mainly lower triangular).

Strings

A finite sequence S of characters is called a string. With zero characters → empty / null string (Λ or λ). The number of characters is the string length.
A string is denoted by enclosing its characters in single or double quotation marks → string constant. It is terminated by \0, stored as the last element of every string: “Hello” → 5 characters + \0 → length 6 as stored (the string itself has 5 characters).
Notation: characters may be lowercase letters (a, b, …) and exponents (powers) denote repetition: a²b³ab² = aabbbabb; (cd)³ = cdcdcd. Concatenation of X and Y is written X‖Y, X·Y or XY.
Concatenation: S1‖S2 = the characters of S1 followed by those of S2. S1 = 'The', S2 = 'End' → 'TheEnd'; S1‖' '‖S2 = 'The End'.
Substring: part of a string. If S = X‖Y‖Z then Y is a substring of S (X, Z non-empty strings); X empty → Y is an initial substring; Z empty → Y is a terminal substring; a proper substring has length(Y) < length(S). 'BE OR NOT' is a substring of 'TO BE OR NOT TO BE'. Written SUBSTRING(string, initial, length), initial = position of the substring’s first character: SUBSTRING('THE END', 4, 4) = ' END'.

String operations I: length, indexing, insertion, deletion

Length: number of characters in a string → LENGTH(string). LENGTH('Computer') = 8.
Indexing (pattern matching): finding the position where a string pattern P first appears in a given text T → INDEX(text, pattern). If P does not appear in T, INDEX = 0. Arguments can be string constants or variables.
T = 'His Father Is The Professor': INDEX(T,'The') = 15; INDEX(T,'Then') = 0; INDEX(T,' The') = 14. With T = 'HIS FATHER IS THE PROFESSOR', INDEX(T,'THE') = 7 — it travels the string and finds the first match (inside FATHER).
Insertion: insert a string S into text T beginning at position K → INSERT(text, position, string): INSERT('ABCDE', 3, 'XYZ') = 'ABXYZCDE' (XYZ starts at position 3).
Deletion: delete the substring that begins at position K with length L → DELETE(text, position, length): DELETE('ABCDEFG', 4, 2) = 'ABCFG'.

String operations II: replacement

Replacement: replace the first occurrence of pattern P₁ by pattern P₂ → REPLACE(text, pattern₁, pattern₂). REPLACE('ABCDE', 'BC', 'X') = 'AXDE'.
2nd type: every occurrence of P in T is replaced by Q. T = XABYABZ, P = AB, Q = C: AB occurs twice, so a loop runs twice — first gives XCYABZ, second gives XCYCZ.
Error: if Q (the replacement) contains P (what is replaced), the loop never ends. T = XAY, P = A, Q = AB: A never disappears → infinite loop.

Pattern matching algorithm

Decides whether or not a given string pattern P appears in a string text T; length(P) ≤ length(T). P and T have lengths R and S, stored as arrays with one character per element. The algorithm finds the INDEX of P in T. 
Algorithm: Pattern matching (P, R, T, S, INDEX)
Step 1. Set K := 1 and MAX := S - R + 1.
Step 2. Repeat Steps 3 to 5 while K <= MAX:
Step 3.     Repeat for L = 1 to R:
                If P[L] != T[K + L - 1], then:
                    Go to Step 5.
            [End of inner loop]
Step 4.     Set INDEX := K and Exit.
Step 5.     Set K := K + 1.
        [End of Step 2, outer loop]
Step 6. Set INDEX := 0.
Step 7. Exit.

T = ababbaabaaab (S = 12), P = abaa (R = 4), MAX = 12 − 4 + 1 = 9.

Linked list (one-way list)

A linear collection of data elements, called nodes, where the linear order is maintained by means of links or pointers. Each node has two parts: the first holds the information of the element; the second, the link field (next pointer field), holds the address of the next node.
The pointer of the last node holds a special value, the null pointer (any invalid address), denoted ✕, signalling the end of the list.
A special pointer START holds the address of the first node. If START = NULL the list has no nodes: a NULL list or empty list.

Arrays vs linked lists

Drawbacks of arrays: (1) once elements are stored it is difficult to insert or delete at any position; (2) arrays have fixed size — memory too large wastes the unused part, memory too small loses data.
Advantage of a linked list: it can dynamically shrink and expand, so you can insert or delete elements efficiently at any position.
Array Linked list
Strength Random access (fast search) · less memory per element · better cache locality Fast insertion/deletion · dynamic size · efficient memory allocation/utilization
Weakness Slow insertion/deletion · fixed size · inefficient memory allocation/utilization Slow search · more memory needed per node

Traversing a linked list

LIST is a linked list in memory; the algorithm applies PROCESS to each element. PTR points to the node currently being processed. 

Algorithm: Traversing a linked list
Step 1. Set PTR := START.
Step 2. Repeat Steps 3 and 4 while PTR != NULL:
Step 3.     Apply PROCESS to INFO[PTR].
Step 4.     Set PTR := LINK[PTR].
        [End of Step 2 loop]
Step 5. Exit.
Algorithm: print the values (info) of the list
Step 1. Set PTR := START.
Step 2. Repeat Steps 3 and 4 while PTR != NULL:
Step 3.     Write: INFO[PTR].
Step 4.     Set PTR := LINK[PTR].
        [End of loop]
Step 5. Exit.
Algorithm: count the number of elements
Step 1. Set NUM := 0.
Step 2. Set PTR := START.
Step 3. Repeat Steps 4 and 5 while PTR != NULL:
Step 4.     Set NUM := NUM + 1.
Step 5.     Set PTR := LINK[PTR].
        [End of loop]
Step 6. Exit.

Searching a linked list

SEARCH(INFO, NEXT, HEAD, ITEM, PREV, CURR, SCAN) — finds the location LOC of the node where ITEM first appears in LIST, otherwise sets LOC = NULL.

For an ascending list, keep moving while ITEM > INFO[PTR]. Time: worst case O(n), average O(n/2). 

Algorithm: SEARCH(INFO, LINK, START, ITEM, LOC)
Step 1. Set PTR := START.
Step 2. Repeat Steps 3 and 4 while PTR != NULL:
Step 3.     If ITEM = INFO[PTR], then:
                Set LOC := PTR and Exit.
            Else:
                Set PTR := LINK[PTR].
        [End of loop]
Step 4. Set LOC := NULL.
Step 5. Exit.
Algorithm: SRCHSL(INFO, LINK, START, ITEM, LOC)  (sorted list)
Step 1. Set PTR := START.
Step 2. Repeat Step 3 while PTR != NULL:
Step 3.     If ITEM > INFO[PTR], then:
                Set PTR := LINK[PTR].
            Else if ITEM = INFO[PTR], then:
                Set LOC := PTR and Exit.
            Else:
                Set LOC := NULL and Exit.
            [End of If structure]
        [End of Step 2 loop]
Step 4. Exit.

AVAIL list & garbage collection

Avail list points to “available space / node”. Together with the linked lists in memory, a special list of unused memory cells is maintained. This list, which has its own pointer, is the Avail list (free-storage list or free pool).
Garbage collection: the O.S. of a computer may periodically collect all deleted or unused space onto the free-storage list. Any technique that does this is called garbage collection. The O.S. performs it whenever it finds the CPU idle or programs falling short of memory space.

Overflow & underflow

Overflow: new data is to be inserted into a data structure but there is no available space, i.e. the free-storage list is empty. The programmer prints OVERFLOW and must add space. In a linked list it occurs when AVAIL = NULL.
Underflow: one wants to delete data from a data structure that is empty. The programmer prints UNDERFLOW. In a linked list it occurs when START = NULL.

Insertion into a linked list

LIST has successive nodes A and B; insert a new node N (info/value + LINK) between them: A’s LINK points to N and N’s LINK points to B. N is taken from the free-storage list.

Insert as first node & at location LOC

AVAIL holds the pointer of the first blank position; NEW stores it. LINK[AVAIL] is the second blank position; assigning it to AVAIL makes the 2nd blank the 1st blank. 

Algorithm: insert ITEM as the first node of the list
Step 1. If AVAIL = NULL, then:
            Write: OVERFLOW and Exit.
Step 2. Set NEW := AVAIL and AVAIL := LINK[AVAIL].
Step 3. Set INFO[NEW] := ITEM.
Step 4. Set LINK[NEW] := START.
Step 5. Set START := NEW.
Step 6. Exit.
Algorithm: insert ITEM at location LOC (after node A; if LOC = NULL, as the first node)
Step 1. If AVAIL = NULL, then:
            Write: OVERFLOW and Exit.
Step 2. Set NEW := AVAIL and AVAIL := LINK[AVAIL].
Step 3. Set INFO[NEW] := ITEM.
Step 4. If LOC = NULL, then:
            Set LINK[NEW] := START and START := NEW.
        Else:
            Set LINK[NEW] := LINK[LOC] and LINK[LOC] := NEW.
        [End of If structure]
Step 5. Exit.

Inserting into a sorted list

Example: ITEM = 35 in 10→20→30→40: SAVE and PTR walk along; 35 < 40 → insert after 30. 

Procedure: FINDA(INFO, LINK, START, ITEM, LOC)
Finds the location LOC of the last node such that INFO[LOC] < ITEM, or sets LOC := NULL.
Step 1. If START = NULL, then:
            Set LOC := NULL and Return.
Step 2. If ITEM < INFO[START], then:
            Set LOC := NULL and Return.
Step 3. Set SAVE := START and PTR := LINK[START].
Step 4. Repeat Steps 5 and 6 while PTR != NULL:
Step 5.     If ITEM < INFO[PTR], then:
                Set LOC := SAVE and Return.
            [End of If structure]
Step 6.     Set SAVE := PTR and PTR := LINK[PTR].
        [End of loop]
Step 7. Set LOC := SAVE.
Step 8. Return.
Algorithm: INSERT(INFO, LINK, START, AVAIL, ITEM)  (sorted linked list)
Inserts ITEM at location LOC in a sorted linked list.
Step 1. Call FINDA(INFO, LINK, START, ITEM, LOC).
Step 2. Call INSLOC(INFO, LINK, START, AVAIL, LOC, ITEM).
Step 3. Exit.

Deletion from a linked list

Delete node N between A and B: A’s LINK skips N to B; N goes back to the free-storage list (AVAIL). 

Algorithm: DEL(INFO, LINK, START, AVAIL, LOC, LOCP)
Deletes the node N at location LOC. LOCP is the location of the node which precedes N (LOCP = NULL when N is the first node).
Step 1. If LOCP = NULL, then:
            Set START := LINK[START].
        Else:
            Set LINK[LOCP] := LINK[LOC].
        [End of If structure]
Step 2. Set LINK[LOC] := AVAIL and AVAIL := LOC.
Step 3. Exit.

Delete the node with a given ITEM

Algorithm: DELETE-NODE(START, INFO, LINK, AVAIL, LOC, LOCP, ITEM)
Step 1. If START = NULL, then:
            Set LOC := NULL and LOCP := NULL, and Exit.
Step 2. If INFO[START] = ITEM, then:
            Set LOC := START and LOCP := NULL.
            Set START := LINK[START].
            Set LINK[LOC] := AVAIL and AVAIL := LOC, and Exit.
Step 3. Set SAVE := START and PTR := LINK[START].
Step 4. Repeat Steps 5 and 6 while PTR != NULL:
Step 5.     If INFO[PTR] = ITEM, then:
                Set LOC := PTR and LOCP := SAVE.
                Set LINK[LOCP] := LINK[LOC].
                Set LINK[LOC] := AVAIL and AVAIL := LOC, and Exit.
Step 6.     Set SAVE := PTR and PTR := LINK[PTR].
        [End of loop]
Step 7. Set LOC := NULL.
        Write: ITEM not in the linked list.
Step 8. Exit.

Delete from the beginning / end

Algorithm: deletion from the beginning of a linked list
Step 1. If START = NULL, then:
            Write: UNDERFLOW and Exit.
Step 2. If LINK[START] = NULL, then:
            Set PTR := START and START := NULL.
        Else:
            Set PTR := START and START := LINK[START].
        [End of If structure]
Step 3. Set LINK[PTR] := AVAIL and AVAIL := PTR.
Step 4. Exit.
Algorithm: deletion from the end of a linked list
Step 1. If START = NULL, then:
            Write: UNDERFLOW and Exit.
Step 2. If LINK[START] = NULL, then:
            Set PTR := START and START := NULL.
            Set LINK[PTR] := AVAIL and AVAIL := PTR, and Exit.
Step 3. Set PTR := START.
Step 4. Repeat Step 5 while LINK[PTR] != NULL:
Step 5.     Set LOC := PTR and PTR := LINK[PTR].
        [End of loop]
Step 6. Set LINK[LOC] := NULL.
Step 7. Set LINK[PTR] := AVAIL and AVAIL := PTR, and Exit.

Header linked lists

A header linked list always contains a special node, the header node, at the beginning. START points to the header node, which holds some extra information about the list. The header node is not part of the list itself; its LINK part contains the address of the first node: LINK[START].
Grounded header list: the last node contains the null pointer. Empty if LINK[START] = NULL.
Circular header list: the last node points back to the header node. Empty if LINK[START] = START.
Why circular? Many operations are much easier: the NULL pointer is not used, so every pointer holds a valid address, and every ordinary node has a predecessor, so the first node needs no special case.

Other variations

Circular list: the last node points back to the first node instead of containing the null pointer.
Linked list with header and trailer node: contains both a special header node at the beginning and a special trailer node at the end.

Two-way (doubly) linked list

A link structure that can be traversed in two directions: forward (beginning → end) and backward (end → beginning). A node N has immediate access to both the next and the previous node — so N can be deleted without traversing any part of the list.
A linear collection of nodes, each divided into three parts: (1) INFO — data of N; (2) pointer field FORW — location of the next node; (3) pointer field BACK — location of the preceding node.
Two list pointer variables: FIRST (first node; sometimes START) and LAST (last node; sometimes END). NULL pointers sit in the FORW field of the last node and the BACK field of the first node.
FIRST + FORW traverse forward; LAST + BACK traverse backward.

Example: hospital BED list

BED stores patient names in an alphabetically sorted two-way list with FORW and BACK; FIRST = 5, LAST = 9, AVAIL = 10. AVAIL follows FORW only (a one-way list), so its BACK entries are blank.

BED Kirk Dean Maxwell Adams Lane Green Samuels Fields Nelson
FORW 7 6 11 12 3 0 4 1 0 2 8 9
BACK 8 5 7 0 1 11 12 3 4

Order: Adams → Dean → Fields → Green → Kirk → Lane → Maxwell → Nelson → Samuels.
